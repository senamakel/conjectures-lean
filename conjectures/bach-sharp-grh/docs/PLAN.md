# bach-sharp-grh: plan and Phase 0 feasibility (2026-11-26)

## Target

Under GRH, for every modulus `m ≥ 3`, every proper subgroup of `(ℤ/m)ˣ` misses a unit
`a ≤ c log² m` with `c = 2/log² 3 = 1.657071…`; equivalently `(ℤ/m)ˣ` is generated by the
classes of the positive integers `≤ c log² m`. The constant cannot be lowered: for `m = 3` the
only non-trivial unit is `2`, and `2 = c log² 3`.

What is published. Bach, *Explicit bounds for primality testing and related problems*, Math.
Comp. 55 (1990) 355–380 (text read through a search-engine extract of the paper, 2026-11-26;
the AMS page itself returned 403):

* Theorem 2 (ERH): if a nontrivial subgroup `G` of `ℤ/(m)*` contains every positive `n < x`,
  then `x < 2 (log m)²`. Here `n` ranges over all positive integers, so a prime `p | m` already
  lies outside `G`; the highly composite moduli are trivial for this form.
* Theorem 3 (ERH): the same with `n` restricted to integers prime to `m`, with `3 (log m)²`;
  checked by computer for `m < 10⁶`. This is the form that generators need, and the form of
  `Ankeny.BachSubgroupBound` (a *unit* outside `H`).
* End of §6: "These computations, and the computations used to verify Theorem 3 for small m,
  showed that in Theorem 2, one can replace "2" by 2/log 3 = 1.657071..., which is the best
  possible constant. Possibly this is also true of Theorem 3, but no attempt has been made to
  verify such a claim." (The extract drops the square: `1.657071 = 2/log² 3`; `2/log 3 = 1.820`.)

So the target is Bach's open question for Theorem 3. Later work: Lamzouri–Li–Soundararajan 2015
Thm 1.1, `(log q + B(q))²` for `q ≥ 3000` (asymptotically constant 1); Bellotti,
arXiv:2610.10177 (2026), quotes `G(n) < 2 log² n` for `n ≥ 2` as Bach's; lls-grh proves the
constant `2` for Theorem 3's form in Lean (`LLS.bach2_of_GRH`).

## 1. The analytic inequality and its threshold `q₀(c)`

The argument is lls-grh's proof of `bach2_of_GRH` (`LLS/Bach2/`). If every unit `≤ x` lies in a
proper subgroup `H`, a character `χ ≠ 1` trivial on `H` gives (`LLS.budget_nonpos`)

    base2(x, Pc) − κ(x) log q − C(q) ≤ 0,

with

* `K = (√x + 1 + ½ log x)/(1 + 1/x − 2/√x)`, `κ = K(1 − 1/x) + ½ log x`;
* `base2 = x − (3/20)√x − 3 log x − 3 + 2K·Pc − 2K·Eshift(x) + ½ log π log x − Etil(x)`,
  `Pc ≤ Σ_{n≤x} Λ(n)/n (1 − n/x)` (exact sum for `x < 2000`, else `log x − 2`),
  `Eshift = −½(1 − 1/x) log π − (γ/2)(1 − 1/x) + (log x + 2)/x`, `Etil = π²/6 − (γ/2) log x`;
* `C(q) = Σ_{p | q, p ≤ x} W_p`, `W_p = A_p + max(0, A_p − κ log p)`,
  `A_p = (log x − ½ log p)²/2 + 2K log p/(p − 1)` (`costQ`, one modulus at a time), or the
  uniform bound `Σ_{p<53} max(0, W_p − β log p) + β log q`, `β = (log x)²/(2 log 53) + 2K/52`
  (`costU`, needs `β ≤ κ`).

So `c` works at `q` as soon as the budget is positive at `x = ⌊c log² q⌋`. A float port of these
formulas (`scratchpad/bachsharp/budget.py`, `badc.c`) reproduces lls-grh's own sizing for
`c = 2` (uniform budget from `2^26.7`, blueprint: from `2^27`; 6,950 moduli failing the
per-modulus budget with `Σ q = 4.3·10^9`, blueprint: about 7,500 and `4.4·10^9`).

Thresholds, `L = log q` (last failing value on a grid of step 0.05):

| `c` | uniform budget positive from | every `q` passes (worst `q` = primorial-like) from |
|---|---|---|
| 2 | `2^26.7` | `2^25.2` |
| 1.95 | `2^28.4` | `2^28.1` |
| 1.9 | `2^30.4` | `2^29.3` |
| 1.85 | `2^32.6` | `2^30.6` |
| 1.8 | `2^35.2` | `2^33.8` |
| 1.75 | `2^38.2` | `2^35.6` |
| 1.7 | `2^41.8` | `2^39.5` |
| **1.657** | **`2^51.1`** (`10^15.4`) | **`2^43.7`** (`10^13.2`, LP bound; `2^43.4` integral) |
| 1.5 | `2^74.5` | `2^66.5` |
| 1.25 | `2^232` | `2^146` |

So `q₀(2/log² 3) ≈ 10^13.2` for the method with exact prime factors, `≈ 10^15.4` for the cheap
uniform test. Moduli with no prime factor `≤ x` pass for every `L` in range at all these `c`:
the obstruction is only moduli with many small prime factors.

The asymptotic tail (`LLS.goodQ_tail2`'s polynomial argument with `L ≤ 0.7769(√x + 1)`,
`0.7769 ≥ 1/√1.657`) closes for `z = x^{1/8} ≥ 9`, i.e. `q ≥ 2^7354`; we use `q ≥ 2^7400`.

## 2. The finite range below `q₀`

lls-grh's checker (`LLSCheck.lean`, soundness `LLS.Check.checkChunk_sound`) walks blocks of
moduli; per block it tries the uniform budget, else every `q` with its own prime factors, else
ankeny-grh's generation search `checkGen` (a breadth-first search over all of `(ℤ/q)ˣ`, cost
`O(q)` time and memory per modulus). Every modulus is needed, not only primes. Measured for
`c = 2`: 1342 s CPU for all `q < 2^2500`; the search handled about 7,500 moduli.

Estimated moduli failing the per-modulus budget at `c = 1.657` (density count over the
x-smooth prime sets, per dyadic bucket; `scratchpad/bachsharp/badc1657.txt`):

| range | failing moduli (cumulative) | `Σ q` over them (cumulative) |
|---|---|---|
| `< 2^17` | 2.0·10^4 | 1.1·10^9 |
| `< 2^20` | 7.6·10^4 | 3.0·10^10 |
| `< 2^24` | 2.9·10^5 | 1.5·10^12 |
| `< 2^28` | 7.0·10^5 | 4.1·10^13 |
| `< 2^32` | 1.08·10^6 | 5.3·10^14 |
| `< 2^36` | 1.23·10^6 | 2.9·10^15 |
| `< 2^40` | 1.25·10^6 | 6.2·10^15 |

(buckets above `2^39` contribute fewer than 600 moduli each; the last failing moduli are near
`2^43.4`.)

Cost with the existing checker at `c = 1.657`: the per-modulus loop must run up to the uniform
threshold `2^51` (`2·10^15` moduli at about `10^5` moduli/s: `~10^10` s), and the search must
visit `Σ q ≳ 3·10^15` group elements with arrays of up to `10^13` entries. **Out of reach.**

What is cheap: the search below `2^17` (D, no GRH; `Σ_{q<2^17} q ≈ 8.6·10^9`, minutes), the
per-modulus budget plus search on `[2^17, 2^20)` (`Σ q ≈ 2.9·10^10` over the failures, under an
hour), and the uniform budget from `2^52` on (one block per octave above `2^100`).

For comparison, the existing checker closes **`c = 1.9` for every `m ≥ 3`** at about 5 CPU-hours
(loop over `2^30.4` moduli ≈ 4 h; search over 2.1·10^4 moduli, `Σ q ≈ 8.5·10^10` ≈ 1 h), and
`c = 1.8` needs a search over `Σ q ≈ 3.6·10^12` with arrays of `4·10^9` entries (not feasible).
Not launched (over the one-hour limit).

### Numerical check of the statement (exact, not in Lean)

`scratchpad/bachsharp/gm.c` computes `g(m)`, the least `y` such that the units `≤ y` generate
`(ℤ/m)ˣ`, by the Frattini test (for each prime `ℓ | φ(m)`, the images of the units in
`G/G^ℓ`, coordinates from discrete logarithms mod `ℓ` in each cyclic factor of
`(ℤ/p^k)ˣ`; for `2^k`, the `±5^e` coordinates). Cross-checked against breadth-first search for
every `m ≤ 3000`. The bound `g(m) ≤ (2/log² 3) log² m` holds for **every `3 ≤ m ≤ 10^7`**, with
equality only at `m = 3`. Largest ratios `g(m)/log² m`:

| `m` | `g(m)` | ratio |
|---|---|---|
| 3 | 2 | 1.657071 (= c) |
| 4 | 3 | 1.561 |
| 6 | 5 | 1.557 |
| 24 | 13 | 1.287 |
| 20 | 11 | 1.226 |
| 8 | 5 | 1.156 |
| 12 | 7 | 1.134 |
| 70 | 19 | 1.053 |

Per decade the maximum is 1.287 (`m = 24`) on `[10, 100)`, 0.778 (`140`) on `[10², 10³)`,
0.710 (`1364`) on `[10³, 10⁴)`, 0.498 (`10824`), 0.492 (`164220`), and 0.407 (`5053620`,
`g = 97`) on `[10⁶, 10⁷]`. The audit's "below 1.06 for every `m ≥ 25`" is confirmed (max
1.0526 at `m = 70`). The truth is far below the constant; the obstruction is purely the
analytic budget for highly composite moduli.

## 3. Decision

**The sharp constant for every `m ≥ 3` is not reachable with the existing machinery.** The gap is
`2^17 ≤ m < 5·2^49` (with the cheap GRH chunks, `2^20 ≤ m < 2^52`). Closing it needs two new
proved-sound checkers:

1. a block checker that enumerates, per block of moduli, the x-smooth squarefree kernels whose
   cost reaches the budget (instead of looping over every modulus up to `2^51`), with a soundness
   proof like `blockOK_sound` (estimated a few hundred lines);
2. a structural generation certificate for each failing modulus (about 1.25·10^6 moduli up to
   `~10^13`): factorisation of `q`, a primitive-root certificate for each prime power, and the
   Frattini rank test for each `ℓ | φ(q)`, proved sound through the CRT decomposition of
   `(ZMod q)ˣ` and characters of prime order (estimated 2–3 weeks of Lean; run time about
   1–3 CPU-hours compiled).

The fallback "two-part" statement (a constant `c₁ < c` for all `m ≥ m₁`) is harder, not easier:
any constant `≤ 1.657` meets the same gap.

What this project proves now (Phase 1):

* `SharpOptimal` (D): no constant below `2/log² 3` works (`m = 3`).
* The sharp bound for `3 ≤ m < 2^17` (D, no GRH; breadth-first search, proved-sound).
* The sharp bound for `m ≥ 5·2^49 ≈ 2.8·10^15` under GRH (C), with constant
  `1.657 < 2/log² 3`: a parametrised copy of lls-grh's checker for `5·2^49 ≤ q < 2^7400`
  (every block passes the uniform budget; `[2^51, 5·2^49)` does not) and the polynomial tail.
* The assembled theorem: under GRH, every proper subgroup misses a unit
  `≤ (2/log² 3) log² m` when `m < 2^17` or `m ≥ 5·2^49`, and `≤ 2 log² m` for every `m`
  (lls-grh's `bach2_of_GRH`), with the gap stated.
